# Оркестратор

Цель: создать фактический результат по исходной задаче, запустить проверки и при включённой независимой верификации проверить результат отдельным субагентом, не участвовавшим в генерации.

Новый пакет использует schema 3. Маршрут задаёт `execution.owner`: `kimi_code` по умолчанию, `kimi_work` только после явного выбора и с `execution.stop_policy: cooperative`.

`execution.mode: team` является режимом по умолчанию. Основная сессия принимает верхнеуровневые решения, декомпозирует работу, назначает модели, ставит задачи и контролирует результат. Содержательную генерацию выполняют согласованные субагенты. `solo` допускается только по явному выбору пользователя, verifier остаётся отдельным субагентом.

Минимальная схема: `T1` создаёт результат и запускает тесты, `T2` независимо проверяет результат. Каждая задача имеет `model`, `effort`, `reason` и назначение из YAML-профиля. Активный профиль и его SHA-256 входят в ревизию пакета. Недоступность model, effort или runtime alias блокирует pre-flight, скрытый fallback запрещён.

Discretionary high и max для исполнительной задачи требуют предшествующей задачи `model_review`. Отдельный model reviewer оценивает только назначение. Его собственное фиксированное назначение и фиксированное назначение verifier не требуют рекурсивного review. Пользовательские override и Work session defaults также не требуют review.

Детерминированную проверку пакета в Code и Work запускает отдельный `package_checker`. Созданный в Code пакет не исполняется создающей сессией: после успешной проверки она сохраняет `LAUNCH.md` и завершает текущий ответ без pre-flight исполнения, запуска DAG, субагентов, реализации и тестов по пакету. Никакие разрешения и последующие сообщения в этой сессии не отменяют запрет. Пользователь вручную открывает новую основную Code-сессию через `LAUNCH.md`. Только в ней после pre-flight реализация начинается сразу без повторного стартового согласования.

Work session defaults применяются при создании и исполнении ко всем субагентам, включая verifier и `package_checker`. В манифесте задачи содержат фактические одинаковые назначения с `assignment_source: work_session_default`.

Параллельно выполнять только независимые задачи в пределах `max_parallel` и разрешения swarm. По умолчанию `max_parallel: 1`. При недоступности swarm использовать последовательное исполнение тех же ролей с записью причины, без model fallback или скрытого solo.

Разрешения на исполнительных субагентов, проверяющие роли, swarm, коммиты, публикацию, установку и необратимые действия проверяются независимо. Согласие на проверку разрешает только проверяющие роли.

После неудачи эскалация model или effort той же задачи записывается с причиной. Discretionary high или max требует нового review. Смена роли или границ требует отдельного согласования.

В Work остановка между завершёнными вызовами устанавливает `cancelled`. После прерывания активного вызова при неподтверждённой целостности устанавливается `interrupted`, автоматическое продолжение запрещено. Не обещать отмену активного foreground вызова.

Оркестратор собирает фактические выходы, журнал и доказательства. Статусы реализации и проверки обновляет раздельно и только в пределах `implementation.scope`. Черновые выходы перечисляются в `implementation.draft_outputs` и не считаются готовым результатом. Schema 2 остаётся legacy и не получает новых обязательных полей.
