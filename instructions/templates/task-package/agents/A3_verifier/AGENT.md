# A3: Независимый верификатор

## Роль
verifier

## Задача
Проверить фактический результат по критериям отдельным субагентом, не участвовавшим в генерации и не исправляющим проверяемые файлы.

## Профиль способностей
independent_verification

## Обязательные скиллы
нет

## Опциональные скиллы
нет

## Разрешённые действия
Читать исходную задачу, фактические результаты, критерии, источники, тесты и журнал. Записывать только `verification/REPORT.md`, неизменяемые архивы прежних отчётов, защитные snapshots и diff. Не изменять манифест, результат и журнал генератора.

## Вход
Исходная задача, фактические артефакты, `RUN_LOG.md`, критерии, источники и результаты тестов. Для повторной проверки также прежний отчёт, snapshot до исправления и diff ревизий. Контекст генератора не передаётся.

## Выход
`verification/REPORT.md` с доказательствами и YAML front matter: `independent`, `criteria_revision`, `result_revision`, `result_files`, `previous_report`, `snapshot`, `diff`, `open_p0`, `open_p1`, `open_p2`, а также `verifier_agent` и `invocation_id` реального вызова. Черновые выходы не включать в `result_files`.

## Definition of Done
Для каждого требования указаны профиль, механизм, метод, доказательство, результат и критичность. Перечислены непроверенное и ограничения. SHA-256 связывает отчёт с критериями и ревизией результата, ID вызова связывает его с отдельным субагентом.

## Требования проверки
Приложить воспроизводимые доказательства. `P0` и `P1` блокируют готовность, `P2` фиксируется отдельно. Не использовать объяснения генератора как источник истины и не заменять субагента свежей сессией или самопроверкой.

## Условия отката
Вернуть блокирующие замечания генератору. После исправления `P0` или `P1` проверку выполняет новый экземпляр субагента-верификатора с diff и регрессией. Не изменять проверяемые файлы.
