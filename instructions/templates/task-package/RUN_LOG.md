# Журнал фактического выполнения

Формат события: `YYYY-MM-DD HH:MM | среда | актор | прежний статус -> новый статус | действие | доказательство | итог`.

После стартового согласования добавляется событие с действием `стартовое согласование пользователя` и явными областями разрешений: исполнительные субагенты, верификатор и `package_checker`, swarm, `max_parallel`, коммиты, публикация, установка и необратимые действия. Значения `allow` без такой записи недействительны.

Для каждого реального субагента записывать роль, доступный ID агента или вызова, время и связанные артефакты. Если стабильный ID недоступен, сохранять фактический след вызова инструмента или процесса и ограничение доказательства. Самодекларация недостаточна.

Для `package_checker` дополнительно сохраняются точная команда, код выхода, stdout, stderr, JSON-результат и `package_revision`. Повторная проверка выполняется новым экземпляром после изменения статических входов.

В Work до каждого вызова фиксируются намерение, входы и ожидаемые выходы. `cancelled` требует записи контролируемой остановки между завершёнными вызовами и отсутствия новых веток. `interrupted` требует сверки целостности и запрета автоматического продолжения до явного решения пользователя.

Для машинной проверки каждое фактическое итоговое событие содержит поля `действие`, `доказательство`, `итог`, `открытые замечания`. Записывать их только после реального действия. Прошлые события не переписывать.
