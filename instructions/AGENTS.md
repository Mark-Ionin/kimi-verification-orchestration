# Верификация и оркестрация

Применять эти правила только к соответствующим задачам, не загружая дополнительные модули без необходимости.

## Постоянные инварианты

- Отвечать на русском. Длинное тире запрещено, использовать `–`.
- Kimi Code является основным исполнителем по умолчанию. Kimi Work создаёт пакет и исполняет его только при явно выбранном `execution.owner: kimi_work`.
- Новые пакеты используют schema 3 и `execution.mode: team` по умолчанию. В team основная сессия оркестрирует, а содержательную генерацию выполняют согласованные субагенты. `solo` допускается только после явного выбора пользователя; адаптивная декомпозиция не является скрытым переходом в solo.
- Каждая задача schema 3 имеет непустые `model`, `effort`, `reason` и разрешённый `runtime_alias` из выбранного YAML-профиля. Недоступность назначения блокирует pre-flight; скрытый fallback запрещён.
- В Code и Work созданный пакет проверяет отдельный `package_checker`. Исполнительные субагенты, verifier, `package_checker` и необходимый model reviewer перечисляются в одном стартовом согласовании.
- Не выдавать план, вызов скилла, статический разбор или декларацию за фактическую реализацию либо проверку.
- При включённой независимой верификации назначать отдельного субагента, не участвовавшего в генерации результата. Свежая сессия и самопроверка не являются заменой.
- Согласие на независимую проверку разрешает только её субагента и `package_checker`. Исполнительные субагенты и swarm требуют отдельных разрешений.
- `P0` и `P1` блокируют готовность. `P2` фиксируется без блокировки и пересматривается при изменении среды или границ задачи.
- Не запускать субагентов без явного разрешения пользователя. Отсутствие такого разрешения не отменяет основную реализацию.
- Не имитировать распределённое выполнение одним агентом.
- Коммиты, публикация, удаление и другие необратимые действия всегда требуют отдельного разрешения.
- Статус и готовность подтверждать фактическими доказательствами, привязанными к объёму задачи и ревизии результата.

## Маршрутизация

- Для включённой проверки результата прочитать `core/verification.md`. Реестр профилей загружать только при выборе или применении профиля.
- Триггер `ПРОМТ –` регистронезависим и требует компактный пакет оркестрации. Прочитать `core/orchestration.md` и адаптер текущей среды.
- В Work использовать `adapters/work.md`. По умолчанию только согласовать задачу и создать пакет. Исполнять пакет в Work только после явного выбора маршрута и согласования всех ролей.
- В Kimi Code использовать `adapters/kimi-code.md`. После стартового согласования и успешного pre-flight сразу исполнять задачу.
- Дизайн-реестр загружать только для визуального продукта или A3.
- Без триггера простой промт может быть одним файлом. Для сложного предложить пакет, но не создавать его автоматически.
- Для большого ответа или документа заранее оценить объём и предложить разбиение на части.
- Для аналитики, выводов и рекомендаций согласовать методологию, ограничения и альтернативы. Для аналитической записки сначала уточнить ключевую мысль.

## Стартовое согласование

До создания файлов один раз показать: цель, ожидаемый результат, границы задачи, критерии приёмки, уровень верификации, содержательные чек-поинты и разрешения.

Согласование разрешает создание пакета и обычную реализацию с тестами в Kimi Code после успешного pre-flight. Повторная остановка только для подтверждения запуска запрещена.

Вопрос о независимой проверке одновременно запрашивает разрешение на отдельного субагента-верификатора. Он не разрешает генераторов, swarm или увеличение параллельности. Для исполнения в Work один явный вопрос перечисляет маршрут, генераторов, верификатора, `package_checker`, возможный swarm и `max_parallel`.

Содержательный чек-поинт не является повторным разрешением на реализацию. Использовать его только для заранее объявленного решения пользователя: методологии, архитектуры, промежуточного результата или иного существенного выбора.

Агентов, DAG и профили способностей показывать заранее только для явно запрошенной многоагентной схемы или если они существенно влияют на риск и стоимость. Их детализацию выполняет основной исполнитель.

Отдельные разрешения требуются только на субагентов, коммиты, публикацию, необратимые действия и действия за пределами согласованных границ.
